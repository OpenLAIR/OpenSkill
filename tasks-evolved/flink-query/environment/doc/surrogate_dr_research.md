To verify the Flink job output independently, you can construct a surrogate test using a small, manually crafted CSV input that mimics the Google Cluster Trace schema. Since the goal is to identify the "longest stage" (defined by a 10-minute inactivity gap for SUBMIT events), you can create a test case where the expected result is mathematically certain.

### 1. Independently Computable Reference Values
Create a small `task_events.csv` file with the following structure (columns: `timestamp` (μs), `missing`, `jobID`, `taskID`, `machineID`, `event_type`). Note: `event_type` 0 is `SUBMIT`.

| Timestamp (μs) | JobID | Event Type | Logic |
| :--- | :--- | :--- | :--- |
| 1,000,000 | 101 | 0 | Start Stage 1 |
| 2,000,000 | 101 | 0 | Stage 1 (2 tasks) |
| 601,000,000 | 101 | 0 | Gap > 10m (600s), Start Stage 2 |
| 602,000,000 | 101 | 0 | Stage 2 (2 tasks) |
| 603,000,000 | 101 | 0 | Stage 2 (3 tasks) |

**Computation:**
*   **Stage 1:** Events at 1s and 2s. Gap to next event (601s) is 599s. Since 599s < 600s (10 minutes), these are in the same window. Wait, the gap is 10 minutes (600,000,000 μs).
*   **Correction:** If the gap is 10 minutes, events at 1s and 2s are in one session. The event at 601s is 599s after the event at 2s. This is *less* than 600s. Therefore, all events (1s, 2s, 601s, 602s, 603s) belong to **one session** of 5 tasks.
*   **Test Case for Split:**
    *   Event A: 1,000,000 (1s)
    *   Event B: 602,000,000 (602s) — Gap is 601s (> 600s).
    *   **Result:** Job 101 has two stages: Stage 1 (1 task), Stage 2 (1 task). Max tasks = 1.

### 2. Dataset-Level Statistical Invariants
*   **Completeness:** The number of unique `jobID`s in the output must match the number of unique `jobID`s present in the input `task_events` file that have at least one `event_type == 0`.
*   **Non-negativity:** The "number of tasks" field must be $\ge 1$ for every job present in the output.
*   **Monotonicity/Bounds:** The `jobID` in the output should be a subset of the `jobID`s found in the input.

### 3. Cross-Validation Approach
You can use a simple Python script (using `pandas`) to compute the ground truth for your test input, which serves as a perfect oracle for your Flink job.

```python
import pandas as pd

# Load test data
df = pd.read_csv('test_task_events.csv', header=None)
df.columns = ['ts', 'missing', 'jobID', 'taskID', 'machineID', 'type', ...]
# Filter for SUBMIT events (type 0)
submits = df[df['type'] == 0].sort_values('ts')

def get_max_session_tasks(group):
    # Calculate gaps between consecutive events
    gaps = group['ts'].diff()
    # A new session starts if gap > 10 minutes (600,000,000 microseconds)
    is_new_session = gaps > 600_000_000
    session_id = is_new_session.cumsum()
    return group.groupby(session_id).size().max()

# Verify against Flink output
expected = submits.groupby('jobID').apply(get_max_session_tasks)
```

*   **Watermarks:** Ensure your test uses a `BoundedOutOfOrdernessStrategy` with a delay (e.g., 1 second) to allow for the out-of-order events typical in these traces.
*   **Session Window:** In Flink, use `.window(EventTimeSessionWindows.withGap(Duration.ofMinutes(10)))`.
*   **Verification:** Your `pytest` should read the output file generated by the Flink job and compare it against the `expected` Series calculated by the Python script above.
