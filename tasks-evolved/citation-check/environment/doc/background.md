# Building a Python Utility for BibTeX Parsing and AI Hallucinated Citation Verification

**Key Points**
*   **AI hallucinations threaten academic integrity:** Large Language Models (LLMs) frequently generate plausible but entirely fabricated citations, complete with fake Digital Object Identifiers (DOIs) and fabricated authors. 
*   **`bibtexparser` 1.4.2 provides stable parsing:** Version 1.4.2 remains widely used for parsing BibTeX files, though it requires specific middleware and string manipulation to clean LaTeX artifacts.
*   **API Verification is complex but feasible:** Free APIs like CrossRef (using the polite pool) and Semantic Scholar can verify citations, though strict rate limits apply when bypassing authentication. 
*   **OpenAlex policy changes affect keyless access:** Recent updates to the OpenAlex API heavily restrict keyless queries to 100 per day, making CrossRef and Semantic Scholar the primary targets for unauthenticated verification.
*   **Fuzzy matching is essential:** Because APIs and BibTeX sources normalize titles and authors differently, deterministic string matching fails; Levenshtein distance and token-based similarity metrics are required.

**The Rise of Fabricated Citations**
As generative AI tools become integrated into academic workflows, the phenomenon of "hallucinated" citations has emerged as a significant threat to scholarly integrity. Models are designed to predict the next plausible token, not to verify factual existence, resulting in references that structurally resemble real academic work but point to nonexistent papers. Verifying these systematically requires automated pipelines.

**Automated Verification Strategies**
To combat this, researchers and developers can construct Python-based validation modules. By parsing bibliographic data structures (like BibTeX) and pinging external metadata databases (CrossRef, Semantic Scholar, DBLP), we can programmatically cross-reference claims. However, this process is fraught with network instabilities, rate limits, and the complexities of fuzzy string matching.

**Navigating API Limitations**
While many academic APIs are ostensibly free, they are protected by aggressive rate-limiting protocols to prevent server overload. Unauthenticated queries—those made without API keys—are severely restricted. Building a robust utility requires implementing exponential backoff protocols, intelligent caching, and respectful polling intervals to ensure continuous operation without triggering IP bans.

## 1. Introduction to the Phenomenon of Hallucinated Citations

The integration of Large Language Models (LLMs) into academic writing has introduced a novel and insidious challenge: the generation of hallucinated citations. LLMs operate as advanced prediction engines, calculating the probability of word sequences based on massive training corpora rather than retrieving verified facts from an internal database [cite: 1, 2]. When prompted to provide sources, an LLM prioritizes linguistic fluency and structural plausibility over factual accuracy [cite: 2, 3].

### 1.1 Characteristics of Hallucinated Citations

Research indicates that a staggering proportion of AI-generated citations are entirely fabricated. Studies analyzing LLM outputs across various psychological subfields have documented false citation rates ranging from 6% to 60% [cite: 4]. A separate analysis of references generated by ChatGPT-3.5 revealed that 47% were completely fabricated, while another 46% cited real references but extracted incorrect information from them [cite: 5].

AI-hallucinated citations typically exhibit several distinct patterns:
*   **Plausible but Non-existent DOIs:** Hallucinations frequently include a Digital Object Identifier (DOI) that mimics the standard format (e.g., `10.1177/03057356211030985`) but leads nowhere [cite: 4, 6].
*   **Chimerical Combinations:** LLMs often stitch together names of legitimate, well-known researchers in a specific field with fabricated but highly relevant paper titles [cite: 4, 7].
*   **Phantom Venues:** Fabricated references may cite convincing but non-existent journals (e.g., *Journal of Applied Neurobiology*), or they may misappropriate the names of legitimate peer-reviewed journals for fake articles [cite: 6].
*   **Misaligned DOIs:** In some instances, the LLM provides a legitimate DOI that resolves to a real paper, but the actual paper's topic, authors, or title have no relation to what the LLM claimed [cite: 4].

These fabrications are difficult to detect manually because they are stylistically perfect, utilizing correct academic formatting, appropriate terminology, and correct issue/volume numbers that correspond logically to the fabricated publication year [cite: 2, 4]. Automated detection is therefore required to cross-reference precise metadata (authors, titles, venues, DOIs) against definitive academic registries [cite: 2].

## 2. Foundational Parsing: Utilizing `bibtexparser` 1.4.2

To verify citations, the raw text must first be structured into a machine-readable format. BibTeX remains the standard for bibliographic data. The Python library `bibtexparser` version 1.4.2 is uniquely suited for this task, offering stability and broad compatibility, although its API differs entirely from the completely rewritten version 2.x [cite: 8, 9]. 

### 2.1 Importing and Loading BibTeX Files

In `bibtexparser` 1.4.2, data is loaded into a `BibDatabase` object, which contains an `entries` attribute (a list of dictionaries representing each publication) [cite: 8, 10]. There is a critical distinction between `bibtexparser.load()` (for file objects) and `bibtexparser.loads()` (for raw strings) [cite: 8].

```python
import bibtexparser
from bibtexparser.bparser import BibTexParser
import re

def parse_bibtex_file(file_path):
    """
    Parses a BibTeX file using bibtexparser 1.4.2 and returns a list of dictionaries.
    """
    # Initialize the parser with customization flags
    parser = BibTexParser(common_strings=True)
    
    # homogenize_fields standardizes field names (e.g., 'URL' becomes 'url')
    parser.homogenize_fields = True
    
    # Allows parsing of non-standard entry types beyond @article, @book, etc.
    parser.ignore_nonstandard_types = False
    
    try:
        with open(file_path, 'r', encoding='utf-8') as bibtex_file:
            # Use .load() for file objects, NOT .loads()
            bib_database = bibtexparser.load(bibtex_file, parser=parser)
            return bib_database.entries
    except FileNotFoundError:
        print(f"Error: File {file_path} not found.")
        return []
```

### 2.2 Accessing Fields and Iterating Entries

By convention in version 1.4.2, uppercase keys like `ID` and `ENTRYTYPE` are generated by the parser, whereas standard BibTeX fields (`title`, `author`, `year`) are converted to lowercase when `homogenize_fields=True` is used [cite: 10, 11].

```python
def process_entries(entries):
    processed_list = []
    for entry in entries:
        # Safely access fields using .get() to handle missing data
        entry_id = entry.get('ID', 'unknown_id')
        entry_type = entry.get('ENTRYTYPE', 'misc')
        
        # Core metadata
        title = entry.get('title', '')
        author = entry.get('author', '')
        year = entry.get('year', '')
        
        # Venue metadata (varies by ENTRYTYPE)
        journal = entry.get('journal', '')
        booktitle = entry.get('booktitle', '') # Used for conference proceedings
        publisher = entry.get('publisher', '')
        
        # Identifiers and locators
        doi = entry.get('doi', '')
        volume = entry.get('volume', '')
        pages = entry.get('pages', '')
        
        processed_list.append({
            'id': entry_id,
            'type': entry_type,
            'title': clean_bibtex_artifacts(title),
            'author': clean_bibtex_artifacts(author),
            'year': year,
            'doi': clean_bibtex_artifacts(doi),
            'venue': clean_bibtex_artifacts(journal if journal else booktitle)
        })
    return processed_list
```

### 2.3 Cleaning BibTeX and LaTeX Artifacts

BibTeX strings frequently contain curly braces `{}` intended to preserve capitalization (e.g., `{C}onvolutional {N}eural {N}etworks`), as well as LaTeX escape sequences for special characters (e.g., `\"o` for `ö`) [cite: 12]. Failing to clean these artifacts will severely degrade fuzzy string matching performance. 

```python
def clean_bibtex_artifacts(text):
    if not text:
        return ""
    
    # 1. Remove curly braces used for capitalization protection in BibTeX
    text = re.sub(r'[{}]', '', text)
    
    # 2. Handle common LaTeX character escapes (simplified heuristic)
    # Note: For exhaustive LaTeX to Unicode conversion, pylatexenc is recommended,
    # but regular expressions suffice for basic artifact removal.
    latex_replacements = {
        r"\\'a": "á", r"\\'e": "é", r"\\'i": "í", r"\\'o": "ó", r"\\'u": "ú",
        r'\\"a': "ä", r'\\"e': "ë", r'\\"i': "ï", r'\\"o': "ö", r'\\"u': "ü",
        r"\\`a": "à", r"\\`e": "è", r"\\`i": "ì", r"\\`o": "ò", r"\\`u": "ù",
        r"\\~n": "ñ", r"\\^o": "ô", r"\\c{c}": "ç", r"\\&": "&", r"\\%": "%"
    }
    
    for latex, unicode_char in latex_replacements.items():
        text = text.replace(latex, unicode_char)
        
    # 3. Clean up multiple spaces and newline characters
    text = re.sub(r'\s+', ' ', text).strip()
    return text
```

Specific gotchas in 1.4.2 involve `@string` macros. If the BibTeX file uses string variables (e.g., `@string{ j_nature = "Nature" }` and then `journal = j_nature`), the `BibTexParser(common_strings=True)` argument allows the parser to interpret standard macro strings without raising formatting errors [cite: 10].

## 3. Landscape of Free Academic Citation Verification APIs

Once the citation is parsed and cleaned, the module must query external databases to verify the existence of the text. The user's requirement to rely on *free APIs without API keys* imposes significant structural limitations, making the choice of endpoints and HTTP header configurations paramount.

### 3.1 The CrossRef REST API (`api.crossref.org`)

CrossRef is the preeminent DOI registration agency and maintains a massive metadata repository. The CrossRef REST API is publicly accessible without an API key, making it the backbone of any free citation verification utility [cite: 13, 14]. 

#### Polite Pool and Headers
CrossRef operates two API pools: a common pool and a "polite pool" [cite: 14]. The common pool is heavily rate-limited and subject to unpredictable timeouts. To enter the polite pool, the application must supply a contact email address, either via a `mailto` query parameter or within the `User-Agent` HTTP header [cite: 13, 14, 15, 16]. 

```python
import requests
import urllib.parse

def query_crossref(title, authors, year, polite_email="your_email@example.com"):
    base_url = "https://api.crossref.org/works"
    
    # Constructing query parameters
    params = {
        "query.bibliographic": title,  # Targets title, author, and abstract
        "rows": 3,                     # Limit results to top 3 for speed
        "mailto": polite_email         # Enters the CrossRef polite pool
    }
    
    # Best practice: Include contact info in User-Agent as well
    headers = {
        "User-Agent": f"PythonCitationVerifier/1.0 (mailto:{polite_email})"
    }
    
    try:
        response = requests.get(base_url, params=params, headers=headers, timeout=10)
        response.raise_for_status()
        data = response.json()
        
        items = data.get("message", {}).get("items", [])
        return items
    except requests.exceptions.RequestException as e:
        print(f"CrossRef API Error: {e}")
        return []
```

#### Interpreting the Response
The CrossRef JSON response wraps results in a `message` object containing an `items` array. Each item provides deeply nested metadata. Because LLM citations may merge legitimate authors with fake titles, it is crucial to parse the returned authors list and publication year to cross-reference against the input [cite: 4].

### 3.2 Semantic Scholar Academic Graph API (`api.semanticscholar.org`)

Semantic Scholar provides an excellent graph of papers and citations. While they strongly encourage API keys, they permit unauthenticated access with a strict global rate limit of **100 requests per 5 minutes per IP address** [cite: 17, 18, 19]. 

```python
def query_semantic_scholar(title):
    # The Academic Graph API search endpoint
    base_url = "https://api.semanticscholar.org/graph/v1/paper/search"
    
    params = {
        "query": title,
        "limit": 3,
        # Requesting specific fields reduces payload size and processing time
        "fields": "title,authors,year,externalIds,venue"
    }
    
    try:
        response = requests.get(base_url, params=params, timeout=10)
        # Handle 429 Too Many Requests specifically due to tight limits
        if response.status_code == 429:
            print("Semantic Scholar Rate Limit Exceeded (100 req/5min).")
            return None
            
        response.raise_for_status()
        return response.json().get("data", [])
    except requests.exceptions.RequestException:
        return []
```

### 3.3 OpenAlex API (`api.openalex.org`)

OpenAlex is an extensive open catalog of scholarly works. **Critical API Update Note:** Historically, OpenAlex mirrored CrossRef by operating a `mailto` polite pool. However, as of early 2025/2026, **OpenAlex has deprecated the polite pool and now requires an API key for meaningful access** [cite: 20, 21]. 

Without an API key, OpenAlex restricts users to a highly constrained testing tier of only **100 credits per day** [cite: 21, 22, 23]. A simple list search (e.g., `/works?search=...`) costs 10 credits, meaning a keyless script will be blocked after just 10 searches [cite: 21]. Therefore, for a keyless utility, OpenAlex should be considered an absolute last-resort fallback, or excluded entirely to prevent immediate `HTTP 409/429` errors.

### 3.4 DBLP API for Computer Science

For computer science literature, the DBLP API is highly reliable, completely free, and does not require an API key [cite: 24, 25]. It accepts queries at the `/search/publ/api` endpoint [cite: 25].

```python
def query_dblp(title):
    base_url = "https://dblp.org/search/publ/api"
    params = {
        "q": title,
        "format": "json",
        "h": 3 # maximum hits to return
    }
    
    try:
        response = requests.get(base_url, params=params, timeout=10)
        response.raise_for_status()
        data = response.json()
        
        # DBLP deeply nests its results
        hits = data.get("result", {}).get("hits", {}).get("hit", [])
        return [hit.get("info", {}) for hit in hits]
    except requests.exceptions.RequestException:
        return []
```

### 3.5 Native DOI Resolution (`doi.org`)

Because AI models frequently hallucinate DOIs [cite: 4], a fast, definitive test is verifying the resolution of the DOI directly. A valid DOI will return an `HTTP 301/302` redirect to the publisher's landing page, or an `HTTP 200` if followed [cite: 1].

```python
def verify_doi_exists(doi):
    if not doi:
        return False
    
    doi = doi.replace('https://doi.org/', '').strip()
    url = f"https://doi.org/{doi}"
    
    try:
        # Use a HEAD request to minimize bandwidth
        response = requests.head(url, allow_redirects=True, timeout=5)
        # 200 indicates the DOI resolves to an actual publisher page
        return response.status_code == 200
    except requests.exceptions.RequestException:
        return False
```

## 4. Matching and Scoring Heuristics

Retrieving results from an API is insufficient; the module must programmatically decide if the retrieved paper is the *same* paper parsed from the BibTeX. Because titles may contain slightly different punctuation, missing subtitles, or differing capitalizations (e.g., Web of Science vs. Scopus norms [cite: 26]), strict string equality (`==`) will result in false negatives [cite: 26, 27].

### 4.1 String Similarity Metrics

Python developers standardly rely on the Levenshtein distance—a metric quantifying the minimum number of single-character edits (insertions, deletions, substitutions) required to change one string into another [cite: 28, 29]. The `thefuzz` (formerly `fuzzywuzzy`) library implements this effectively [cite: 26, 28].

*   **Simple Ratio:** Compares entire strings. Highly sensitive to word order.
*   **Partial Ratio:** Matches the shortest string against sub-strings of the longer string. Ideal if a subtitle was dropped [cite: 28].
*   **Token Sort Ratio:** Tokenizes the strings, sorts the words alphabetically, and then compares them. This is vital because academic titles might rearrange clauses [cite: 28, 29].

### 4.2 Normalization Pipeline

Before applying Levenshtein algorithms, strings must be normalized to strip away noise [cite: 27]:

1.  Lowercase all characters.
2.  Remove punctuation and special characters (hyphens, colons, commas).
3.  Remove stop words or articles (e.g., "a", "an", "the").

```python
import string
from thefuzz import fuzz

def normalize_string(text):
    if not text:
        return ""
    text = text.lower()
    # Remove punctuation
    text = text.translate(str.maketrans('', '', string.punctuation))
    # Remove common English articles
    articles = [' a ', ' an ', ' the ']
    for article in articles:
        text = text.replace(article, ' ')
    # Normalize whitespace
    return ' '.join(text.split())

def calculate_similarity(bib_title, api_title):
    norm_bib = normalize_string(bib_title)
    norm_api = normalize_string(api_title)
    
    # Token sort ratio is most robust against academic title variations
    score = fuzz.token_sort_ratio(norm_bib, norm_api)
    return score
```

### 4.3 Multi-Factor Confidence Scoring

Relying solely on the title is dangerous. An AI might hallucinate a paper titled "The effects of cognitive behavioral therapy on depression" [cite: 7], which is generic enough to closely match a real paper by completely different authors. A robust utility employs a multi-factor heuristic:

*   **Title Match (Score 0-100):** Weighted at 50%
*   **Author Overlap:** Extract last names from the BibTeX and API response. If at least one primary author matches, award 30 points.
*   **Year Match:** If publication years match exactly, award 20 points. Allow a $\pm 1$ year tolerance for preprint-to-publication lag.

*Threshold Logic:* A composite score $\geq 85$ indicates a highly probable real citation [cite: 27]. A score between 70 and 85 requires manual review. A score $\leq 70$, especially if the DOI fails to resolve, almost certainly flags a hallucination [cite: 4, 7].

## 5. Practical Implementation of Robust API Querying

When scraping thousands of citations using unauthenticated API endpoints, network failures, timeouts, and rate limits are inevitable. Bypassing these issues requires enterprise-grade resilience using the `requests` library.

### 5.1 Retry Logic and Exponential Backoff

When an API returns an HTTP 429 (Too Many Requests) or an HTTP 500/502/503/504 (Server Error), the script should pause and retry, increasing the wait time exponentially between attempts [cite: 17, 30]. The `urllib3` library, packaged within `requests`, provides the `Retry` object to automate this.

```python
import time
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

def get_robust_session():
    session = requests.Session()
    
    # Configure retry strategy
    # backoff_factor = 1 means sleep times will be [0s, 2s, 4s, 8s, 16s]
    retry_strategy = Retry(
        total=5,  # Maximum number of retries
        backoff_factor=1,
        status_forcelist=,
        allowed_methods=["HEAD", "GET", "OPTIONS"]
    )
    
    adapter = HTTPAdapter(max_retries=retry_strategy)
    session.mount("http://", adapter)
    session.mount("https://", adapter)
    
    return session
```

### 5.2 Polite Pacing

Even with retry logic, hammering Semantic Scholar with 100 requests in 10 seconds will trigger an immediate ban. Because Semantic Scholar allows 100 requests per 5 minutes [cite: 17, 18], the script should enforce a hardcoded delay of at least 3 seconds between requests (since 300 seconds / 100 requests = 3 seconds/request) [cite: 19, 31].

```python
def rate_limited_query(session, url, params, headers=None, delay=3.0):
    try:
        response = session.get(url, params=params, headers=headers, timeout=10)
        # Enforce rate limit pause
        time.sleep(delay)
        response.raise_for_status()
        return response.json()
    except requests.exceptions.RequestException as e:
        print(f"Request failed: {e}")
        return None
```

## 6. Navigating Edge Cases, Pitfalls, and Data Anomalies

Academic metadata is notoriously messy. A verification utility will crash or produce false positives if it does not gracefully handle structural anomalies [cite: 26, 27].

### 6.1 BibTeX Entries with Missing Fields
AI hallucinations or poorly maintained reference managers frequently output BibTeX blocks missing required fields, such as `year` or `doi` [cite: 2].
*Solution:* The script must never rely on dictionary key existence (e.g., `entry['doi']`). Always utilize `entry.get('doi', None)` and structure conditional branching to fallback to title/author search if the DOI is absent.

### 6.2 Partial Matches and Obscure Papers
CrossRef may return a partial match where the title is identical, but the year is different by several years. This typically happens when comparing a pre-print (e.g., arXiv) to a final journal publication. 
*Solution:* Ensure the matching heuristic incorporates a `venue` check. If a paper is genuinely too new or obscure, APIs will return 0 results. The utility should flag these as "Unverified," not strictly "Fake," to alert the human researcher to investigate manually.

### 6.3 Unicode and Math Formulas in Titles
Physics and mathematics papers frequently feature LaTeX math notation in the title (e.g., `$O(N)$ symmetry`). CrossRef often indexes the raw string or strips it entirely. 
*Solution:* Perform aggressive regex stripping of text trapped between `$` markers during the `normalize_string()` step before submitting to `thefuzz`. 

### 6.4 Conference Proceedings vs. Journal Papers
`bibtexparser` keys shift depending on the `@type`. An `@inproceedings` block utilizes the `booktitle` key for the conference name, whereas an `@article` block uses `journal`. 
*Solution:* Concatenate or dynamically fetch `entry.get('journal') or entry.get('booktitle') or entry.get('series')` to ensure the venue is captured regardless of the publication type.

## 7. Structuring the Output Pipeline

The final step is aggregating the verification results into an auditable, machine-readable JSON file. This file should be formatted for easy integration into subsequent data pipelines or dashboards, ensuring strict encoding and organized sorting.

### 7.1 JSON Dumping Strategy

The output must be serialized using `json.dumps()`. Critical formatting requirements include:
1.  **Ensuring ASCII encoding is false:** Setting `ensure_ascii=False` forces Python to write actual UTF-8 characters (like `é` or `ö`) instead of unreadable unicode escape sequences (`\u00e9`).
2.  **Alphabetical sorting:** Setting `sort_keys=True` ensures the output dictionary is standardized, allowing for easy `git diff` comparisons between runs.
3.  **Indentation:** Using `indent=4` provides human-readable formatting.

```python
import json

def export_results(verification_results, output_file="verification_report.json"):
    """
    Exports the validation dictionary to a clean JSON file.
    """
    # Separate fake citations for specific analysis
    fake_citations = [res for res in verification_results if res['status'] == 'Fake']
    
    # Sort fake citations alphabetically by author, then title
    fake_citations.sort(key=lambda x: (x.get('author', ''), x.get('title', '')))
    
    report = {
        "metadata": {
            "total_processed": len(verification_results),
            "total_fake": len(fake_citations),
            "total_real": len(verification_results) - len(fake_citations)
        },
        "fake_hallucinated_citations": fake_citations,
        "all_results": verification_results
    }
    
    with open(output_file, 'w', encoding='utf-8') as f:
        # Proper encoding, sorting, and indentation
        json.dump(report, f, ensure_ascii=False, indent=4, sort_keys=True)
        
    print(f"Report cleanly exported to {output_file}")
```

### 7.2 The Holistic Pipeline

A complete verification loop integrates the aforementioned components in the following chronological sequence:
1.  Initialize `bibtexparser` with `homogenize_fields=True`.
2.  Iterate through `bib_database.entries`.
3.  Clean LaTeX formatting and curly braces from the title and author strings.
4.  Check if `doi` exists. If so, ping `doi.org`. If it resolves, mark as `Real`.
5.  If DOI fails or is absent, initialize the robust `requests.Session`.
6.  Query CrossRef (polite pool) utilizing title and author.
7.  Apply `fuzz.token_sort_ratio` between the BibTeX title and CrossRef hits.
8.  If CrossRef returns no strong match, wait 3 seconds and query Semantic Scholar.
9.  Compile composite heuristic scores.
10. Categorize as `Real`, `Fake/Hallucinated`, or `Unverified`.
11. Execute `json.dump` to write the output matrix.
